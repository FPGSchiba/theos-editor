Researcher probes (supporting evidence only, not reproduced): D9, D10

Scope notes. "monaco.d.ts" means the file `package/monaco.d.ts` of the 0.57.0 tarball [D2]. "esm source" means files under `package/esm/vs/` of the same tarball [D4–D7]. Counts from the GitHub search API are keyword searches and include noise; the query is given each time [D11]. All dates are 2026-10-31 unless stated.

## Byte-stable Markdown

- The document is the text model: a piece-tree text buffer (`PieceTreeTextBuffer`) over the raw string, edited with `applyEdits` / `pushEditOperations` on line/column ranges. Markdown is not parsed into a tree; the bundled Markdown language (`esm/vs/languages/definitions/markdown/markdown.js`) is a Monarch `tokenizer` definition (token colouring), with no match for `[!`, "callout" or "wikilink" in the file [D4] [D12] [D2] [D8].
- Load then read back without edits (buffer built the way `createModel` builds it, read with `getValueInRange`), measured on 0.57.0 [D9]:
  - identical: pure LF, pure CRLF, no final newline, trailing spaces and tabs, three blank lines in a row, `e` + U+0301, U+00A0, an emoji surrogate pair, U+2028, U+0085 [D9].
  - changed: a file with mixed line ends is rewritten to one line end; the model picks CRLF when more than half of the line ends are CR or CRLF, otherwise LF (`_getEOL`), and `normalizeEOL` is on by default. `a\r\nb\r\nc\nd\r\n` reads back as `a\r\nb\r\nc\r\nd\r\n`; `a\nb\nc\r\nd\n` reads back as `a\nb\nc\nd\n` [D4] [D9].
  - changed: a lone `\r` is treated as a line break and rewritten to the model line end (`a\rb\nc\n` reads back as `a\nb\nc\n`) [D4] [D9].
  - changed: a leading BOM is removed from the buffer and kept in `getBOM()`. `model.getValue(eol, preserveBOM)` adds it back only when `preserveBOM` is true; the default is false [D4] [D9].
- The model holds one line end (`\n` or `\r\n`). `getValue(EndOfLinePreference)` can return the text with LF or CRLF whatever the model holds, so a pure CRLF file can be written back as LF [D2] [D9]. The spec's corpus lists one CRLF file and no mixed-line-end file (spec §4.2, read in this repo).
- Edits: text inserted through `applyEdits` has its line ends converted to the model line end (an `X\nY` insert into a CRLF model became `X\r\nY`) [D4] [D9].
- Span level: an `applyEdits` replace of a range on a five-line string with trailing tab, trailing spaces and blank lines gave exactly the string splice, all other bytes unchanged [D9]. Not run: typing, select-all and type, paste and undo through the editor widget (needs a browser) [D9].
- Positions map to source offsets: `getOffsetAt` / `getPositionAt` use the model text (UTF-16 code units; CRLF counts as 2; `getOffsetAt(2,1)` on `ab\r\ncd\r\n` returned 4) [D2] [D9]. `IModelContentChangedEvent.changes[]` carries `range`, `rangeOffset`, `rangeLength` and `text` for every change, ordered end to start [D2].
- Options that change typed or pasted text by default and have an off switch in the typings: `autoClosingBrackets`, `autoClosingQuotes`, `autoSurround`, `autoIndent`, `formatOnType`, `formatOnPaste`, `trimAutoWhitespace` (default true, "remove trailing auto inserted whitespace"), `unusualLineTerminators` (default `prompt`, offers to remove U+2028/U+2029), `unicodeHighlight` (decorations only; "ambiguous and invisible characters are highlighted" by default) [D2].
- `model.setValue()` replaces the buffer, destroys all decorations and clears the edit history (`_commandManager.clear()`) [D4].

## Front matter untouched

- Read-only exists for the whole editor only: `readOnly`, `domReadOnly`, `readOnlyMessage`, and the event `onDidAttemptReadOnlyEdit`. monaco.d.ts has no read-only range and no editable-range API. Its events are `onDidChangeModelContent` (after the change), `onDidPaste`, `onKeyDown` / `onKeyUp`, `onDidCompositionStart` / `onDidCompositionEnd` and the mouse events; none is documented as running before an edit with a way to veto it [D2].
- Feature requests for ranges: "Provide ability to block editing specific lines" #953, open since 2018-07-10, 152 reactions, labels `feature-request` and `editor-core`; no member comment found in the thread [D16] [D11]. "API to hide parts of the code" #45, open since 2016-07-01, 29 reactions, last update 2026-03-26 [D17].
- #45 history: a maintainer (2016-08-15) pointed to a non-API `setEditableRange`, a later commenter says it is gone; `setHiddenAreas` exists on the editor widget class (`codeEditorWidget.js`) but is not declared in monaco.d.ts, and a commenter (2018-07-19) notes it hides whole lines, not columns [D17] [D5] [D2].
- `setHiddenAreas` normalises ranges to whole-line ranges (`normalizeLineRanges`); `ICodeEditor.onDidChangeHiddenAreas` is public. A commenter (2024-09-25) reports hidden content is still found by Find [D5] [D2] [D17].
- Workarounds named in sources: intercepting `editor.onKeyDown` and calling `preventDefault` when a selection intersects the range (comment in #953, with the author's later note "There are many special cases to deal with.") [D16]; the community package `constrained-editor-plugin` 1.4.0 (published 2025-02-05, MIT; its repository was last pushed 2023-08-14) [D37].
- Source mode: the whole file is one model, so the same component shows the raw file; the protection of the first lines needs one of the workarounds above. The spec also allows splitting the front matter off in Write mode and re-attaching it on save (spec §4.3 criterion 2) [D2] [D4].

## Inline link chips

- Decoration types in monaco.d.ts (`IModelDecorationOptions`): `className`, `inlineClassName` (CSS on the real text of the range), `beforeContentClassName` / `afterContentClassName`, `before` / `after` (injected text), `hoverMessage`, `isWholeLine`, `stickiness`, `zIndex`, per-decoration `fontFamily`, `fontSize`, `fontWeight`, `fontStyle`, `lineHeight`, and the glyph-margin, lines-decoration, margin, overview-ruler and minimap options [D2].
- Injected text (`InjectedTextOptions`): `content` is a plain string that "must be a single line", with `inlineClassName`, `attachedData` and `cursorStops` (`Both`, `Left`, `Right`, `None`; default `Both`). It is part of the view only, not of the model [D2].
- No decoration option replaces or hides a range of real text. Whole lines can be hidden by folding or by the editor-internal `setHiddenAreas`; nothing hides part of a line [D2] [D5].
- DOM widgets: `IContentWidget` (a DOM node placed near a position with a preference list, `allowEditorOverflow`; it is not laid out in the text flow), `IViewZone` (a full-width DOM node between lines, `afterLineNumber`, `heightInPx`), `IGlyphMarginWidget`, `IOverlayWidget`. monaco.d.ts has no inline DOM node that takes space inside a line [D2].
- Caret stepping: `cursorStops` governs stops around injected text. monaco.d.ts has no atomic-range option for real text; a search of monaco-editor issues for "atomic ranges" returned 0 results [D2] [D11].
- `[[` popup: `languages.registerCompletionItemProvider` with `triggerCharacters`; `CompletionItem` fields are `label`, `kind`, `tags`, `detail`, `documentation` (`string | IMarkdownString`), `sortText`, `filterText`, `preselect`, `insertText`, `insertTextRules`, `range`, `commitCharacters`, `additionalTextEdits`, `command`; the editor shows them in its own suggest widget, and no field is typed as a DOM node [D2].
- Broken state: `monaco.editor.setModelMarkers(model, owner, markers)` (squiggles, hover) or an `inlineClassName` decoration. Marker squiggles are read with `take: 500` per model in `markerDecorationsService.js`; a request to make it configurable is open (#5176) [D5] [D47]. Model decorations come from an interval tree with no such cap in the source read [D4].
- Link detection and opening: `languages.registerLinkProvider`, option `links`, `editor.registerLinkOpener`, `registerEditorOpener` [D2].
- Tokenizing `[[id]]` and `[[id|text]]`: `languages.setMonarchTokensProvider` accepts a custom Monarch definition; tokens become coloured spans [D2].

## Callouts with their own look

- Whole-line looks: `isWholeLine` with `className`, `linesDecorationsClassName` (bar next to the text), `marginClassName`, `blockClassName` / `blockPadding` / `blockIsAfterEnd`, per-decoration `lineHeight` (a multiplier), `fontFamily`, `fontSize` [D2].
- Text stays plain model text; decorations do not change it, so editing in place is the normal state [D2] [D4].
- Open issues around per-range line height and font size: "Apply decoration lineHeight on all affected lines after line wrapping" (vscode #249967, open, 2025-05-28) and "Line breaks incorrectly when variable font size" (vscode #288873, open, 2026-01-19; text with a larger font overflows the wrap column) [D43].
- Flagging developer words inline: `inlineClassName` decorations computed by the host, or `setModelMarkers`; `hoverMessage` takes `IMarkdownString` [D2].
- A multi-line construct such as `> [!voice]` is classified by the host's decoration code or by a Monarch tokenizer with state; the stock Markdown definition has no callout or wikilink rule [D2] [D4].
- Folding: `folding` (default true), `showFoldingControls`, `foldingStrategy`, `languages.registerFoldingRangeProvider`. Glyph margin: option `glyphMargin` (default false in monaco-editor), decoration `glyphMarginClassName` / `glyphMargin`, and `IGlyphMarginWidget` [D2].

## Beat headings with attribute lines

- A beat heading and its `key:: value` lines are plain model lines. A change of one value is an edit of that line's range, so the other bytes stay as in the buffer (see Byte-stable Markdown) [D4] [D9].
- Showing the heading and the attribute row as in `04-script.html` with Monaco primitives: whole-line `className` and `before` / `after` injected strings with classes for chip styling, or a view zone whose `domNode` holds a mounted component between lines (a separate DOM row, not the editable `key:: value` text) [D2].
- A finding on its beat: a marker on the heading range (`setModelMarkers`), a glyph-margin or lines-decoration class, an overview-ruler mark (`overviewRuler` option), or `hoverMessage` [D2].
- Beat sections as foldable ranges: `registerFoldingRangeProvider` [D2].

## Spell check and IME

- Input is never a `contenteditable`. The string "contenteditable" does not occur in `esm/vs/editor` or `esm/vs/base` [D6] [D5].
- Two input paths: a native `EditContext` path and a hidden `<textarea>` path. Option `editContext` defaults to true; the effective value is `editContext && typeof globalThis.EditContext === 'function'`. The d.ts describes it as "the new experimental edit context ... instead of the text area"; 0.53.0 added it [D5] [D6] [D2] [D3].
- Both input elements are created with `spellcheck="false"`, `autocorrect="off"` and `autocapitalize="off"` (`textAreaEditContext.js:127-130`, `nativeEditContext.js:77-80`). The native path also creates an `aria-hidden` helper `<textarea>` (`_imeTextArea`) [D6]. monaco.d.ts has no spell-check option [D2].
- The EditContext explainer states: "Using the EditContext will make the native spellchecking capabilities of the browser unreachable." and that these features "won't happen automatically for web-based editors using the EditContext" [D29].
- EditContext support (caniuse, read 2026-10-31): Chrome 121+, Edge 121+, no Firefox, no Safari up to 27.2 (also iOS). MDN marks it experimental and not Baseline [D30] [D31]. A Monaco bug report states the textarea path is used in "Safari / any WKWebView — no EditContext support" [D20]. Whether the WebView2 runtime of a given install is 121 or newer is not settled here (Unknowns).
- Native spell check requests: "Spell checking using browser spell checker" #1977, open since 2020-05-23, 16 comments, 38 reactions, labels `feature-request` and `editor-core`, no member among the commenters; "[Feature request] Spell check" #4442, open, filed as a duplicate of #1977 [D14] [D15] [D11]. A commenter (2025-03-06) notes that the editor adds and removes DOM content as the user scrolls, which prevents third-party DOM inspection [D14].
- Third-party spell check: `monaco-spellchecker` 0.6.0 (MIT; published 2025-01-01; Typo.js plus `setModelMarkers` plus a code-action provider; 4 stars, repo last pushed 2025-01-02) [D38] [D14].
- Because no native spell check runs on Monaco text, there is no per-range switch to turn it off for ids, chips and attribute lines (none in monaco.d.ts) [D6] [D2].
- Composition handling: `ICodeEditor.onDidCompositionStart` / `onDidCompositionEnd` are public; the native path calls `viewController.compositionStart()/End()` and `viewModel.onCompositionStart()/End()` on the browser's `compositionstart` / `compositionend`; the textarea path has code for macOS composition, Android and iOS special cases [D2] [D6].
- IME and dead-key issues, state as of 2026-10-31 [D11] [D26]:
  - monaco-editor, label `editor-input-IME`: 4 open [D11]. Open IME/composition issues: #3549 Japanese IME with `wordWrap` (2023-02-11), #4805 decorations not updating after `compositionstart` on Windows (v0.52.2, 2025-01-17, second reporter 2025-05-12), #4796 line jumps when typing Chinese in Safari (2024-12-28; a 2026-07-13 comment reproduces it on 0.55.1 and places it in the textarea path), #1848 "…" written twice with Firefox and Japanese IME (2020), #2199 Chinese IME with a completion provider (2020) [D22] [D18] [D19] [D23] [D11].
  - Safari/WebKit textarea path: #5390 "First keystroke typed over a backward selection is dropped" (open, 2026-07-16, a comment says it also affects Edge); #5207 typing with a backward selection fails with `editContext: false` (open, 2026-01-30; a 2026-03-19 comment says it is gone in 0.56.0-dev builds) [D20] [D21].
  - VS Code (same core), label `editor-input-IME`: 30 open issues; label `editor-edit-context`: 15 open, 104 closed. Examples open: #324435 Japanese IME reconversion duplicates text with EditContext (2026-07-06), #320074 duplicate text after Japanese conversion (2026-06-05), #271715 multi-cursor with Japanese IME (2025-10-16), #259570 Chinese IME cursor jump (2025-08-04) [D26].
  - Dead keys: VS Code #252129 "EditContext: dead key not considered" (US International on macOS) was closed on 2025-06-23 and labelled `insiders-released`; Monaco #1851 (doubled diacritics, macOS US International) was closed 2022-01-28; Monaco #1524 (dead keys inserted in read-only mode) was closed 2020-01-30 [D24] [D48]. VS Code #326160 (a dead key as a shortcut or first chord key leaves dead-key composition active; Finnish layout; open, 2026-07-16) and #282752 (shortcuts with dead keys broken on Linux since 1.107.0; open, 2026-05-26 update) are open [D25] [D26]. VS Code #299253 (Ctrl+Shift+` not working on German (Switzerland) layouts; open, 2026-03-04) concerns keybindings [D26]. A search of the monaco-editor repo for "dead key" found only the closed items above and unrelated closed ones [D11].
- Microsoft's own hybrid Markdown editor in VS Code (`vscode.markdown.editor`, package `@vscode/markdown-editor` 0.0.2-0, MIT, depends on micromark and katex, no `monaco-editor` dependency) uses a focusable `div` with an attached EditContext and, per its issue #328932, "no hidden native editor". Its open issues include CJK IME on Enter (#337197, 2026-09-22) [D28] [D27].

## Long documents

- Rendering keeps a window of rendered lines (`_rendLineNumberStart` plus a `_lines` array in `viewLayer.js`) rather than one DOM line per model line; read from source, not measured [D5].
- Size thresholds in `textModel.js`: `largeFileOptimizations` (default true) turns off tokenization above 20 MB or 300,000 lines (`LARGE_FILE_SIZE_THRESHOLD`, `LARGE_FILE_LINE_COUNT_THRESHOLD`); `getValue()` throws above 256M characters; the model is not synced to the worker above 50 MB. Defaults `maxTokenizationLineLength` 20,000 and `stopRenderingLineAfter` 10,000 [D4] [D2]. The spec's typical, large and stress files (about 5 KB, 250 KB, 2.5 MB; spec §4.2) are below the file-size thresholds above [D4].
- Fonts and wrap: `fontFamily`, `fontSize`, `lineHeight`, `letterSpacing`, `wordWrap` (`off`, `on`, `wordWrapColumn`, `bounded`), `wrappingIndent`, `wordBreak`, `disableMonospaceOptimizations`, `wordWrapIndicator` (new in 0.57.0) are options [D2] [D3].
- The wrap column is computed as viewport width divided by `typicalHalfwidthCharacterWidth`. `wrappingStrategy` `simple` (default) is described in the editor as "Assumes that all characters are of the same width ... works correctly for monospace fonts and certain scripts (like Latin characters) where glyphs are of equal width"; `advanced` "Delegates wrapping points computation to the browser. This is a slow algorithm, that might cause freezes for large files, but it works correctly in all cases." Accessibility mode forces `advanced` [D5].
- With a non-monospace font (`fontInfo.isMonospace` false) or `disableMonospaceOptimizations`, lines are rendered as `RenderedViewLine` (positions read from the DOM) instead of `FastRenderedViewLine`; a `WebKitRenderedViewLine` variant exists [D5].
- Open reports on wrapping cost: VS Code #117106 "Advanced wrapping strategy causes hangs for larger files" (10 MB, 80,000 lines; open since 2021-02-20, last update 2022-07-09); Monaco #5311 memory stays high after closing a ~50 MB file with `wrappingStrategy: "advanced"` in Electron (open, 2026-04-29) [D40] [D39].

## Svelte 5 integration

- No official Svelte binding. The README links no framework wrapper; `monaco-editor` is a framework-free library with `monaco.editor.create(domNode, options)` and `dispose()` [D12] [D2].
- Community wrappers found (npm search "monaco svelte", read 2026-10-31) [D35] [D36]:
  - `svelte-monaco` 1.0.4 (MIT; last published and last pushed 2025-04-20; 15 stars; peer deps `monaco-editor >=0.50.0 <1`, `svelte >=4.0.0`). Its `Monaco.svelte` uses Svelte 5 runes (`$state`, `$props`, `$bindable`, `$effect`), loads Monaco through `@monaco-editor/loader` `loader.init()` and calls `editor.setValue(value)` whenever `value` differs from the editor text [D35].
  - `@monaco-editor/loader` 1.7.0: "By default all sources come from CDN"; default config is `https://cdn.jsdelivr.net/npm/monaco-editor@0.55.1/min/vs`; `loader.config({ monaco })` uses a local npm package instead [D34].
  - `modern-monaco-svelte` 0.5.0 (MIT; created 2026-06-02; 0 stars; peer `svelte ^5.0.0`, `modern-monaco >=0.3.8`) wraps `modern-monaco`, which loads editor modules, grammars and themes from `esm.sh` at runtime unless the `cdn` option is changed [D36].
  - `monaco-editor-svelte` and `@monaco-editor/svelte` do not exist on npm (404); `svelte-monaco-editor` was unpublished 2023-05-16 [D35].
- Mount and tear down in a component: `const editor = monaco.editor.create(node, opts)` in `$effect`, `editor.dispose()` and `model.dispose()` on cleanup (README: editors and models are disposables; a model keeps its URI until disposed) [D12] [D2].
- Design-system Svelte components inside the editor: `IViewZone.domNode` and `IContentWidget.getDomNode()` take any `HTMLElement`, so `mount(Component, { target })` can render into them; `InjectedTextOptions.content` is a string, so chips cannot be Svelte components there [D2].
- Push changes without re-creating the editor: `editor.createDecorationsCollection(...).set(...)`, `model.deltaDecorations`, `monaco.editor.setModelMarkers(model, owner, markers)`, `editor.changeViewZones`, `editor.updateOptions` [D2].
- Keymap: `KeyMod.CtrlCmd` is mapped to Ctrl on Windows/Linux and to Cmd on macOS (`keybindings.js`: `ctrlKey = OS === Macintosh ? winCtrl : ctrlCmd`; `metaKey = OS === Macintosh ? ctrlCmd : winCtrl`). Binding APIs: `editor.addCommand(keybinding, handler, context)` per editor, `editor.addAction`, and the namespace-level `editor.addKeybindingRule({keybinding, command, when})` / `addKeybindingRules`; chords through `KeyMod.chord`. `IKeybindingRule.command` is typed `string | null` [D2] [D5]. The typings do not say whether a null command removes a built-in binding (Unknowns).
- External change as a minimal edit: `model.applyEdits(ops)` edits "without adding the edits to the undo stack" and the typings warn of "dire consequences on the undo stack"; `model.pushEditOperations(beforeCursorState, ops, cursorStateComputer)` lands on the undo stack; `editor.executeEdits(source, edits, endCursorState)` lands on the undo stack without an undo stop [D2].
- Undo API: `model.pushStackElement()`, `popStackElement()`, `editor.pushUndoStop()`, `popUndoStop()`, `model.undo()` / `redo()`, `canUndo()` / `canRedo()`, `model.getVersionId()` (increments on every change including undo) and `model.getAlternativeVersionId()` ("will return the same values in the case of undo-redo"). monaco.d.ts has no call that clears the undo history; `model.setValue()` clears it (and all decorations); `editor.setModel()` switches to a model with its own history; `saveViewState()` / `restoreViewState()` exist [D2] [D4].
- Content events carry `isUndoing`, `isRedoing`, `isFlush` and `isEolChange` [D2].
- Build and loading, no CDN. Monaco from npm is ESM; the package loads no network resource by itself (see Licence), and the codicon font is a bundled file. Workers: `self.MonacoEnvironment.getWorker(workerId, label)` or `getWorkerUrl(workerId, label)`; the default label uses `editor.worker`, and the json, css, html and ts workers are separate files for the language services. Without a usable worker Monaco logs "Could not create web worker(s). Falling back to loading web worker code in main thread, which might cause UI freezes" and runs the worker code on the main thread; with a bundler URL missing it throws "You must define a function MonacoEnvironment.getWorkerUrl or MonacoEnvironment.getWorker" [D7] [D13]. The README says pages on `file://` cannot create workers and must be served over `http://` or `https://` [D12]. The Vite recipe in the docs returns `new Worker(url, { name: label, type: 'module' })` built from `?worker` imports [D13]. 0.53.0 deprecated the AMD build and stopped custom AMD workers from working out of the box [D3].

## Unknowns

- Whether front matter bytes stay identical through typing, delete at the body start, select-all and type, paste and undo in Source mode with each workaround (key interception, `constrained-editor-plugin`, hidden first lines, split-off front matter). A prototype must run the §4.6 edits and diff the bytes.
- Whether a `[[…]]` range can be shown as a chip (inline class hiding the raw text plus injected text, or `font-size: 0` style tricks) with correct caret stepping, selection geometry, Backspace and Delete as one unit, and correct line wrapping. No source documents hiding real text with a decoration; the prototype must measure caret and selection rectangles in both input paths.
- How the suggest widget can show kind glyphs and filter by allowed kinds, and whether the design system's LinkAutocomplete component can replace it (the typings show no custom-DOM hook).
- Composing next to an injected-text stop: no issue or doc found. IME and dead-key behaviour next to injected text and with decorations in WebView2 (EditContext path), WKWebView and WebKitGTK (textarea path), on Swiss and German layouts; Windows IME with decorations (#4805) on 0.57.0. No source read names WebKitGTK; a search of monaco-editor issues for "webkitgtk" found 0 results [D11].
- Which WebView2 runtime version users have (EditContext needs Chrome or Edge 121 or newer per caniuse [D30]); the sources read here do not state the distribution mode of the app.
- Whether Monaco's module workers (`new Worker(url, { type: 'module' })`; module workers need Chrome/Edge 80, Safari 15, Firefox 114 per caniuse [D32]; WebKitGTK not checked) start under Tauri 2's custom protocol in all three webviews, and which `worker-src` and `style-src` the app's CSP needs. Monaco appends `<style>` elements at runtime (`domStylesheets.js` `createStyleSheet`, no nonce handling found), and Tauri's CSP page says Tauri adds nonces and hashes to bundled code and assets; the combination is untested. The Tauri CSP page does not mention `worker-src` [D7] [D33].
- Bundle behaviour in the real app build (Vite): the measured sizes in Svelte 5 integration used esbuild 0.25.0, not Vite or the app's build; whether the core-only bundle runs a working editor with copy, paste, undo and keybindings was not tested. #5507 says tree-shaken language-service bundles pull in all editor features.
- Measurements of typing latency, scroll cost, open time and memory for the typical, large and stress files, with `wordWrap` on, a proportional font and `wrappingStrategy` `simple` versus `advanced`.
- Whether a proportional font with `wrappingStrategy: 'simple'` wraps visibly wrong lines (the option text says it is exact for monospace and equal-width glyph scripts [D5]); a prototype must look at it with the chosen font.
- Whether per-decoration `fontFamily` / `fontSize` / `lineHeight` (present in the 0.57.0 typings) are stable API for headings and chips: the CHANGELOG does not mention them [D3] and two related VS Code issues are open [D43].
- How hidden or folded first lines behave under select-all, Find, undo and multi-cursor (hidden areas are line-based and a 2024 comment in #45 says Find still matches hidden content [D17]).
- Whether an `IKeybindingRule` with `command: null` removes a built-in binding (Ctrl/Cmd+K chords, Ctrl/Cmd+D and others that clash with the app keymap), and how the single app keymap of G13 would map onto `KeyCode` values on Swiss and German layouts.
- The behaviour of `trimAutoWhitespace`, auto-closing of `[[` and Markdown list auto-continuation with all auto-edit options off; whether the stock Markdown language configuration still inserts text.
- Whether the Svelte community wrappers work with Svelte 5.57 and 0.57.0 (`svelte-monaco` uses `@monaco-editor/loader` with its CDN default and its last release is 2025-04-20 [D35] [D34]); not tested.
- Whether `pnpm licenses list` for a real prototype shows the same set as the package notices (not run here).
