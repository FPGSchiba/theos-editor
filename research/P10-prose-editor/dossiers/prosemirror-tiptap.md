Form tags. **[PM]** = plain ProseMirror (`prosemirror-model`, `-state`, `-view`, `-markdown`, plus `-history`, `-keymap`, `-commands`, `-transform`). **[TT]** = Tiptap (`@tiptap/core`, `@tiptap/markdown`, `@tiptap/starter-kit`, `@tiptap/pm`, Svelte support). **[both]** = true of both, because Tiptap is built on the same `prosemirror-*` packages (`@tiptap/pm` 3.32.2 depends on `prosemirror-view ^1.42.6`, `prosemirror-model ^1.25.12` and others) [D11]. "Probe" = a measurement by the researcher on 2026-10-31 (Node v24.19.0, Windows 11, Intel Core Ultra 7 270K Plus, 24 logical cores, 31.3 GB), run with the packages above installed into a scratch directory outside the repo; inputs and outputs are given in the bullets so they can be repeated [D53, D54, D55]. Nothing here is a score.

## Byte-stable Markdown

Document model
- [PM] The source text is not kept. `defaultMarkdownParser` is `MarkdownParser(schema, MarkdownIt("commonmark", {html: false}), tokens)`: markdown-it tokenizes, handlers build a ProseMirror tree, and `MarkdownSerializer.serialize(doc)` writes Markdown from the tree again. The package pins `markdown-it ^14.0.0`; `markdown-it` latest on npm is 15.0.3, the installed nested copy is 14.3.3 [D2, D1, D53].
- [TT] The source text is not kept. `@tiptap/markdown` parses with `marked` (dependency `^17.0.1`, installed 17.0.6) into Tiptap JSON through each extension's `parseMarkdown`, and `editor.getMarkdown()` is `manager.serialize(editor.getJSON())`, i.e. the whole document is serialized again on every call [D10, D1].
- [TT] The docs call the Markdown extension "a early release" that "can be subject to change or may have edge cases that may not be supported yet" [D13]. The basic-usage page says "Include all needed extensions or content may be lost" and, under the sentence "Test round-trip conversion to ensure your custom Markdown content survives parse → serialize", gives an example that runs `editor.commands.setContent('# Hello **World**', { contentType: 'markdown' })` and then `const result = editor.getMarkdown() // Should match original` [D14].
- [TT] Tiptap's `Document` renders its children joined with `'\n\n'`, so one blank line is written between any two top-level blocks [D11].

What the stock `prosemirror-markdown` serializer changed [PM] (default schema and serializer, 1.13.9; input in, output out; probe) [D53]
- Emphasis: `_a_` and `__b__` come back as `*a*` and `**b**`. The mark specs write `*` and `**` only [D2, D53].
- Bullet lists: `-`, `+` and `*` all come back as `*` (the serializer writes `(node.attrs.bullet || "*")`; the stock schema has no `bullet` attribute). Nested indent is normalized to two spaces per level [D2, D53].
- Ordered lists: numbers are rewritten from the start number (`1. 1. 1.` becomes `1. 2. 3.`; `1. 2. 10.` becomes `1. 2. 3.`; `9. 10.` becomes ` 9. 10.` with padding); `1)` becomes `1.` [D2, D53].
- Loose and tight lists survive through a `tight` attribute (`- one\n\n- two` stays loose) [D2, D53].
- Headings and rules: setext headings become ATX (`Title\n=====` becomes `# Title`); `## H ##` becomes `## H`; `#   Spaced` becomes `# Spaced`; `***` and `___` become `---` [D2, D53].
- Blank lines: a run of blank lines collapses to one, and exactly one blank line is written between blocks (`flushClose(2)`); two adjacent lists of the same type are separated by two blank lines (`flushClose(3)`). The output has no final newline: `x\n` comes back as `x` [D2, D53].
- Soft line breaks (hard-wrapped source lines): the parser's `softbreak` handler adds a single space, so `line one\nline two\nline three` comes back as `line one line two line three`. A hard break written as two trailing spaces comes back as backslash plus newline; trailing spaces at line ends are removed [D2, D53].
- Escaping: `esc()` backslash-escapes `` ` * \ ~ [ ] _ `` (not `_` between two word characters) and, at the start of a block, `+ `, `-`, `*`, `>`, `#` runs and `1.`. So `[[char-001]]` comes back as `\[\[char-001\]\]`, `> [!voice] Alice` as `> \[!voice\] Alice`, `a ~ b` as `a \~ b`, `snake_case_word and _lead` as `snake_case_word and \_lead`. An already escaped `\[\[x\]\]` comes back unchanged [D2, D53].
- Code: `~~~` fences become backtick fences; indented code becomes a fenced block; the fence length grows to exceed any backtick run inside [D2, D53].
- Links and entities: link titles in `'single'` quotes become `"double"`; reference definitions (`[a][1]` plus `[1]: …`) are inlined; `<http://a b>` destinations become `http://a%20b`; `&amp;` and `&copy;` are decoded to `&` and the copyright sign; CRLF becomes LF; `<https://example.com>` and bare URLs come back unchanged [D53].
- Not covered by the stock parser: strikethrough (`~~x~~` comes back as `\~\~x\~\~`) and tables. The `commonmark` preset has no table rule and the stock schema has no table node, so `| a | b |\n|---|---|\n| 1 | 2 |` becomes one paragraph, written back as `| a | b | |---|---| | 1 | 2 |` [D2, D53]. Two issues in the package tracker, "How to handle tables?" (#84) and "How to use with Tables?" (#116), are closed [D42].
- HTML: the parser is built with `html: false`, so `<div>raw</div>` stays literal paragraph text and prints back unchanged [D2, D53].
- Lazy continuation: `> a\nb` becomes `> a b` [D53].

What the stock Tiptap Markdown extension changed [TT] (`StarterKit` + `Markdown`, 3.32.2, through `setContent(md, {contentType: "markdown"})` then `getMarkdown()`; probe) [D54]
- Bullets: `-`, `+`, `*` all become `-`; a loose list is written tight; ordered lists are renumbered (`1. 1. 1.` becomes `1. 2. 3.`); `_a_` and `__b__` become `*a*` and `**b**`; `***`/`___` become `---`; setext becomes ATX; `## H ##` becomes `## H` [D54].
- Blank lines: runs of blank lines are kept as empty paragraphs (`a\n\n\n\nb` comes back unchanged); the docs describe this and an option to turn it off is requested in issue #8592 (open). Changelog 3.29.0: "Fixed blank lines being dropped after block elements" [D16, D27, D56, D54].
- Final newline: no `\n` after a last paragraph, but `\n\n` after a last list, blockquote, rule, heading or fenced block (`- one\n- two\n` comes back as `- one\n- two\n\n`) [D54].
- Soft line breaks: hard-wrapped lines stay as a literal `\n` inside one text node (JSON: `{"type":"text","text":"line one\nline two"}`) and come back as `line one\nline two`; issue #8136 (open) reports that such text renders as visible line breaks. A hard break written as backslash-newline comes back as two spaces plus newline; two trailing spaces are kept [D54, D23].
- Escaping: `\*`, `\_`, `\[`, `\]` are written like the PM serializer, but `_` is also escaped between word characters (`char_one` becomes `char\_one`); `&` becomes `&amp;` and an existing `&copy;` becomes `&amp;copy;` (issue #8471 open); a second round trip of escaped text is reported unstable in #8519 (open) [D54, D25].
- Autolinks: `<https://example.com>` and bare `https://example.org` come back as `[https://example.com](https://example.com)` and `[https://example.org](https://example.org)` (the `Link` extension is part of StarterKit, `autolink: true`, `linkOnPaste: true`) [D54, D11].
- HTML and tables: with only StarterKit, `<div>raw</div>` becomes the text `raw` and a pipe table becomes the empty string; the docs say tables need the Table extension and allow "only one child node per cell" [D54, D14, D13].
- CRLF becomes LF. Front matter text is not recognised (see next section) [D54].
- `StarterKit` also registers `TrailingNode` (adds a trailing empty paragraph unless `trailingNode: false`), input rules (heading, italic, strike, code, code block, horizontal rule, bullet and ordered list, link), and `Link`/`Underline`/`ListKeymap`; each can be set to `false` in `StarterKit.configure` [D11, D21].

Corpus measurement (stock schemas, front matter split off by regex, body only; 17 files of `research/P10-prose-editor/corpus/records`; probe) [D55]
- [PM] 5 of 17 bodies came back byte-identical: 4 are empty bodies and 1 is a single line without final newline (`synthetic-no-final-newline`). The 12 others changed. In those 12 files, 105 of 246 body lines (set membership, not a diff) no longer occur verbatim in the output [D55].
- [TT] The same 5 of 17 came back identical; in the same 12 changed files 69 of 246 body lines no longer occur verbatim [D55].
- These stock schemas have no wikilink, callout or beat nodes, so the numbers are a baseline for stock behaviour, not a prediction for a Theos schema [D55].

Custom node plumbing
- [TT] An extension adds Markdown support with `markdownTokenName`, `markdownTokenizer` (a `marked` extension: `name`, `level` `'block'` or `'inline'`, `start`, `tokenize(src, tokens, lexer)` returning a token with `raw`), `parseMarkdown(token, helpers)` and `renderMarkdown(node, helpers, ctx)`. The helpers `createBlockMarkdownSpec`, `createInlineMarkdownSpec` and `renderNestedMarkdownContent` are exported from `@tiptap/core` [D10, D9, D16, D15].
- [TT] Probe, custom inline atom node `wikilink` (attrs `id`, `text`) with a tokenizer regex `^\[\[([^\]|\n]+)(?:\|([^\]\n]*))?\]\]`: `See [[char-001]] and [[char-001|Alice]] here.`, `[[a|]] [[a b]]`, and attribute lines `speaker:: [[char-001]]\nmood:: calm` came back unchanged apart from the final newline; the same node inside `**…**` lost the bold (`**bold [[x]]**` came back as `**bold** [[x]]`), which matches open issue #8314 ("marks are dropped on inline atom nodes") [D54, D24].
- [TT] Probe, custom opaque block nodes that store `token.raw` in an attribute and write it back (one for `## Beat n — name` plus `key:: value` lines, one for `> [!voice] …` blocks): 2 of 4 inputs came back byte-identical (a `beat, callout, beat` sequence, and a paragraph followed by a callout at the end of the file); the other 2 differed by the missing final newline after a last paragraph, and by extra blank lines when a beat block and a callout block touched with no blank line between them. Those nodes were atoms, so their text was not editable in place [D54].
- [TT] `MarkdownManager` registers custom tokenizers on the global `marked` singleton and never removes them, so two editors in one process share tokenizers (issue #8316, open). The extension option `marked` (`Markdown.configure({marked})`) lets the host inject its own `marked` instance [D26, D10].
- [PM] Custom handling goes through `ParseSpec` (`block`, `node`, `mark`, `ignore`, `getAttrs(token, tokenStream, index)`, `noCloseToken`) and `MarkdownSerializer(nodes, marks, options)` node and mark functions; `strict: false` skips unknown node and mark types; `escapeExtraCharacters` adds escaped characters [D2].
- [PM] Probe: after `parser.tokenHandlers.softbreak = state => state.addText("\n")` (`tokenHandlers` is marked `@internal` in the typings), `line one\nline two\nline three` and `a *b*\nc **d** e` came back equal to the source minus the final newline; a `> [!voice] Alice\n> Hello there.` block differed only by the `\[!voice\]` escape [D2, D53].
- The community package `tiptap-markdown` 0.9.0 (2025-09-08) wraps `markdown-it` and `prosemirror-markdown` for Tiptap (`@tiptap/core ^3.0.1` peer); no release in the last 12 months [D50].

Source positions (can a change be mapped back to source offsets?)
- [PM] markdown-it block tokens carry `map = [line_begin, line_end]` (line numbers, end exclusive); inline tokens and their children have `map = null` and no offsets; `markup` holds the marker (`-`, `##`, `*`). `prosemirror-markdown` discards `map` and `markup` and its stock schema has no attribute for them [D8, D2, D53].
- [PM] Probe: with block specs `getAttrs: tok => ({map: tok.map})` and a schema that adds a `map` attribute to paragraph, heading, blockquote, lists and code blocks, each top-level block carried its line range (`heading [0,1]`, `paragraph [1,2]`, `blockquote [3,5]`, `bullet_list [6,8]`), and slicing the source by those lines returned each block's exact source lines. Text nodes carried no position [D53].
- [TT] `marked` tokens carry `raw`, "a string containing all of the text that this token consumes from the source"; the docs do not say that the `raw` values add up to the source. Probe on one sample (heading, paragraph, blockquote, list, fence, blank-line runs): the top-level `raw` strings concatenated gave the source exactly. Inside a blockquote the child tokens' `raw` omits the `> ` prefix (child paragraph `raw` is `[!voice] Alice\nHello **there**.`), so offsets inside containers cannot be rebuilt from child `raw` alone. Tiptap passes the token (with `raw`) to `parseMarkdown`, and the resulting JSON has no offsets unless the node stores them [D12, D54, D10].
- [PM] ProseMirror transactions carry step maps for document positions, and `Fragment.findDiffStart` / `findDiffEnd` are public; these map document positions, not source offsets [D4, D5].

Prior art
- Third-party benchmark (secondary source, 2026): prosemirror-markdown 1.13 and Tiptap 3.31 with `@tiptap/markdown` changed 7 to 100 percent of lines on 6 simulated files and returned 0 of 6 byte-identical; a CodeMirror 6 reference that patches only edited ranges returned 6 of 6 identical [D51].
- Third-party Java library `prosemirrorfx-markdown` (Apache-2.0, 0 stars, 2 commits, unpublished at read time): each block remembers its source text, marker, indentation and preceding blank lines, unchanged blocks are written from the stored text, and tables, rules, block quotes, HTML blocks and setext headings are kept as plain text. It is built on `prosemirror-kotlin`, not on the JavaScript packages [D52].
- The `prosemirror-markdown` 1.13.9 package ships no source-preserving mode in its source or README; its tracker has no issue about it among the 3 open and the closed issues read [D2, D42].

## Front matter untouched

- [both] Neither form has front matter handling. `prosemirror-markdown`'s source contains only one stale comment about "front matter fences" in `code_block`, and `@tiptap/markdown`/`@tiptap/core` sources contain no front-matter code [D2, D10, D9].
- [both] Probe: a body that still starts with `---\nid: x\n---\n\n# Title\n` parses as a horizontal rule, a setext heading `## id: x`, then the title; written back as `---\n\n## id: x\n\n# Title` ([PM]) and `---\n\n## id: x\n\n# Title\n\n` ([TT]). The front matter has to be split off before parsing [D53, D54].
- [both] Tools for protecting a front matter region exist at the schema and state level: `NodeSpec.content`, `atom`, `selectable`, `isolating` ("sides … count as boundaries that regular editing operations, like backspacing or lifting, won't cross"), `code`, `whitespace: "pre"`; `PluginSpec.filterTransaction` (cancel a transaction) and `appendTransaction`; Tiptap `Document` has `content: 'block+'` and extensions can add ProseMirror plugins with `addProseMirrorPlugins` [D4, D5, D11, D9].
- [both] Neither form documents a raw or Source view of the whole file. The document is a tree; the Markdown text exists only as a string produced by the serializer [D2, D10, D47].
- [TT] `setContent` replaces the whole document (`tr.replaceWith(0, doc.content.size, nodes)`) [D9].

## Inline link chips

- [both] `NodeSpec.inline: true` with `atom: true` ("a single unit in the view"), `selectable` and `draggable` are schema flags. A `NodeView` can supply `dom`, `contentDOM`, `update`, `selectNode`/`deselectNode`, `setSelection`, `stopEvent`, `ignoreMutation` and `destroy`; mark views have the same shape and gained `update` in prosemirror-view 1.42.0 (2026-07-01) [D4, D3].
- [TT] Tiptap's node view API (`addNodeView`, vanilla JavaScript) returns an object with `dom` and optionally `contentDOM`; the docs say Tiptap adds `contenteditable="false"` to non-editable parts by default and point projects that already use React or Vue to those frameworks as the easier route. The node-view pages do not mention Svelte. `@tiptap/react` and `@tiptap/vue-3` are published packages at 3.32.2; their node view renderers were not read for this dossier [D18, D1].
- [TT] `@tiptap/extension-mention` 3.32.2 is an inline atom node (MIT) with `renderText`, `renderHTML` and a Markdown spec; it uses `@tiptap/suggestion`, whose options include `char`, `allowedPrefixes` (default `[' ']`), `startOfLine`, `allowSpaces`, `decorationTag`, `items` and a `render()` with start, update, key-down and exit callbacks. `char` may be longer than one character (the query is `match.slice(char.length)`), and the match is searched in the text node before the caret. The plugin state tracks `editor.view.composing` [D11, D54].
- [TT] Open issue #8432: a Mention label containing a double quote is cut off after a Markdown round trip [D22].
- [PM] No suggestion or autocomplete plugin is part of the `prosemirror-*` packages listed. A community package `prosemirror-suggest` 3.0.0 (MIT, last modified 2024-07-30) exists [D1].
- [PM] Probe, stock serializer: a wikilink without a custom node is written with escapes (`\[\[id|text\]\]`); keeping `[[id]]` verbatim needs a custom schema node plus a markdown-it rule or a text-level handler, or custom serializer logic [D53, D2].
- [both] prosemirror-view releases that touch atom inline nodes: 1.42.6 (2026-09-25) puts a dummy `img.ProseMirror-separator` before an inline atom at the start of a block or right after another atom ("On Safari and Firefox, work around skipped cursor positions and odd cursor drawing"; the maintainer says Chrome needs it too); issue #1599 (open) reports that a wide inline atom at the start of a textblock then leaves an empty first line. 1.41.7 (2026-03-18) and 1.41.4 (2025-12-01) work around Chrome and Safari inserting a bogus `<br>`/hard break when backspacing before a widget or inline-flex node. 1.42.4 (2026-09-18) lets non-editable elements inside node views stop blocking cursor motion [D3, D35, D36].
- [both] Issue #1585 (closed 2026-08-26): on some Windows machines a Chinese IME duplicated the first character after an inline-flex atom; the maintainer judged it "almost certainly a bug in Chrome or the IME system", did not reproduce it, and the reporter's workaround was changing the wrapper from `inline-flex` to `inline-block` [D34].
- [PM, TT] Caret stepping over a chip, deletion of the whole chip, and the `[[` popover are not measured here; they need a browser (see Unknowns) [D3].

## Callouts with their own look

- [both] No callout node exists in the stock packages: the Tiptap repository's package list has `extension-blockquote` and `extension-details` but no callout; `prosemirror-markdown`'s schema has `blockquote` only [D22, D2].
- [both] A callout is a custom block node: a schema node with `content: "block+"` (or inline content) and a `kind` attribute, a node view with `contentDOM` for text that stays editable in place, and a parse rule for `> [!voice] …` [D4, D3].
- [PM] Probe: the stock parser turns `> [!voice] Alice\n> Hello there.\n> More text` into a blockquote whose paragraph text starts with `[!voice] Alice`, and writes it back as `> \[!voice\] Alice Hello there. More text` (soft breaks to spaces) [D53].
- [TT] Probe: the same input comes back as `> \[!voice\] Alice\n> Hello there.\n> More text\n\n` [D54].
- [PM] A markdown-it plugin `markdown-it-obsidian-callouts` 0.3.5 (Apache-2.0, last modified 2026-10-02) exists on npm; not evaluated here [D1].
- [TT] Block-level `markdownTokenizer` is the Tiptap route for such syntax (see Custom node plumbing) [D16].
- [both] Inline flags in voice text ("developer words", `Design note:`) fit inline decorations: "Inline decorations add styling or attributes … to all inline nodes in a given range"; `DecorationAttrs` accept `class`, `style`, `nodeName` and any other DOM attribute [D47, D3].
- [both] Related prosemirror-view facts: 1.42.7 (2026-10-22) "decoration sets with lots of node decorations inside a single parent would require quadratic time to update" fixed; issue #1582 (open) "Allow inline decorations to wrap marks and inline nodes"; issue #1560 (open) "Inline decorations cause incorrect anchor/head behavior during keyboard selection (Shift + Arrow) in Safari" [D3, D32, D38].

## Beat headings with attribute lines

- [PM] Probe: `## Beat 1 — Opening\nspeaker:: [[char-001]]\nmood:: calm\n\nText` parses as a heading and a paragraph (the two `key::` lines joined by a soft break) and is written back as `## Beat 1 — Opening\n\nspeaker:: \[\[char-001\]\] mood:: calm\n\nText`; a blank line is inserted after the heading, the lines are joined with a space, and `[[…]]` is escaped. With the softbreak handler changed to keep `\n`, the lines stay on separate lines [D53].
- [TT] Probe: the same input comes back as `## Beat 1 — Opening\n\nspeaker:: \[\[char-001\]\]\nmood:: calm\n\nText` (blank line inserted after the heading; the attribute lines stay on separate lines) [D54].
- [TT] A custom raw block node holding the heading plus its attribute lines was written back byte-identical when blank lines surrounded it (see Byte-stable Markdown); editing one parameter inside such an opaque node was not tested [D54].
- [both] A finding "on the beat that causes it" can be a node decoration (`Decoration.node`: "add styling or other DOM attributes to a single node's DOM representation"), recomputed from plugin state when the host sends findings [D47, D3].
- [both] A parameter row with chips inside a node view needs the row to be either node attributes rendered by the node view, or a node with inline content; both are custom schema work [D4, D3].

## Spell check and IME

Spell check
- [both] The view's root element is an ordinary `contenteditable` element; typing is left to the browser. The guide says "interfering with that tends to break spell-checking". `EditorProps.attributes` sets attributes on the editable element; ProseMirror's default is `contentEditable` from the `editable` prop plus the class `ProseMirror` [D47, D3].
- [both] Neither prosemirror-view nor `@tiptap/core` sources set or read a `spellcheck` attribute (searched), so the browser default applies. A `spellcheck="false"` attribute can be put on any element through node `toDOM`, a node view, or a decoration (`DecorationAttrs`: "Any other properties are treated as regular DOM attributes") [D3, D9, D58].
- [TT] Tiptap injects a `<style>` tag with ProseMirror's base CSS (`white-space: pre-wrap`/`break-spaces`, `.ProseMirror [contenteditable="false"] { white-space: normal }`) by default (`injectCSS: true`, with an `injectNonce` option) [D9].
- [both] A 2020 forum thread names spellcheck and grammar tools (browser extensions, Apple's spellchecker) as the most cited factor that could be isolated for lag on large documents in Chrome; the thread did not confirm the effect with measurements [D44].

IME and composition
- [both] `EditorView.composing` reports an active composition. prosemirror-view lets the browser edit the DOM and reads it back; the changelog lists these composition fixes since 2024-10-31 (all in releases of prosemirror-view): 1.37.1 (2024-12-11) Chrome misreporting the selection during composition; 1.39.3 (2025-05-14) delete the selection on composition start only across blocks; 1.41.0 (2025-09-06) "a Safari issue that broke composition right after changing the set of active marks"; 1.41.4 (2025-12-01) Chrome on Windows composition before an absolutely positioned widget; 1.41.5 (2026-01-14) Chrome misreporting the cursor and breaking composition, and "a newly introduced bug in Safari where composition in an empty table cell causes it to move the text out of the cell"; 1.41.9 (2026-06-10) Chrome no longer fires key events for backspace during composition; 1.42.4 (2026-09-18) "some types of composition input starting with a non-empty selection"; 1.42.9 (2026-10-31) "the editor could dispatch Enter or Backspace keys during composition" [D3].
- [both] Regression window: prosemirror-view 1.42.7 (2026-10-22) and 1.42.8 produced issue #1610 (open at read time): Backspace during a Chinese IME composition cancels the composition when a `handleKeyDown` handler dispatches an empty transaction. Reproduced in Chromium with CDP composition input in plain ProseMirror and in Tiptap. Fix: 1.42.9; the reporter confirmed the maintainer's patch fixes it in his app (2026-10-31). The Tiptap side, issue #8626 (open), says Tiptap's core Backspace handler uses `commands.first(...)`, which dispatches even when every sub-command returns false [D33, D29, D3, D9].
- [both] Open and closed IME issues: prosemirror tracker, 13 open issues with composition/IME/CJK in the title as of 2026-10-31 (the newest #1610, #1551; the oldest from 2019) [D32]. Tiptap, 11 open issues with "IME" in the title and 4 with "composition" in the title (at least one of those four is about Vue's Composition API) [D22].
- [both] Chromium on Windows: issue #1551 (open, created 2025-11-12) CJK composition duplicating or removing characters on Windows Chromium; the maintainer could not reproduce it as of 2026-01-08 [D37].
- [both] WebKit: prosemirror tracker open issues with Safari/WebKit/iOS in the title: 18, including #971 (2019, marks with style when CJK IME in Safari), #934 (2019, composition text replacement in Safari removes empty nodes), #1462 (2024, Safari visual selection with custom nodes). [TT] Tiptap #7271 (open, created 2025-11-26): Chinese IME in a Heading on WebKit leaves the pinyin next to the committed characters on the first conversion of an empty heading; labels `needs-info`, `type: upstream`; one commenter develops a Tauri app; also open #6825 (IME at the start of a list item in Safari) and #7186 (IME in table cells leaves raw pinyin in Safari) [D32, D30, D22].
- [both] Closed issue #1597 (2026-09-30): an IME composition inside an inline node with text content was detected as Backspace; patch the same day [D41].
- [TT] `@tiptap/suggestion` keeps `composing` in its plugin state, still matches while `view.composing` is true (a source comment cites Tiptap issue #1449), and does not reset its active state on a caret move out of the range while a composition is active [D11].
- [PM] Dead keys and Swiss/German layouts: no prosemirror or Tiptap issue about dead keys (`^`, `¨`) was found. The one German-layout issue found, #1529 ("ü" triggered a ";" binding), was closed 2025-05-04 with prosemirror-keymap 1.2.3: the keyCode fallback now runs only while Ctrl, Alt or Meta is held, and on Windows Ctrl+Alt (AltGr) is not treated as a modifier for that fallback [D40, D7].
- [both] The reproduction in #1610 uses CDP `Input.imeSetComposition`; no ProseMirror or Tiptap test setup for composition on WebKit was found [D33].

## Long documents

- [both] The whole document is rendered as DOM; there is no virtualization. Maintainer reply, 2025-01-12: "ProseMirror doesn't provide any virtualization"; profiling showed the slowdowns were mostly browser layout and editing handling, and he suggests not rendering some content (virtualizing or splitting across pages) [D43].
- [both] The guide says the view compares old and new documents so that typical updates do "very little work", and that unchanged subtrees are shared between document versions [D47].
- [both] 2020 forum reports: lag at "50+ pages" and at about 3,000 words in Chrome and Brave but not Safari or Firefox; the maintainer reported documents in the "million-character range" working well in Chrome on Linux; hiding nodes with `display: none` via decorations made a large document responsive in one report; one reporter saw the same lag in a plain `contenteditable` [D44].
- [PM] Serializer cost, probe (default parser and serializer 1.13.9, Node, no DOM): `typical` 5.1 KB parse 1 ms, serialize 1 ms; `large` 247 KB (1,837 blocks) parse 18 ms, serialize 173 ms; `stress` 2.47 MB (18,337 blocks) parse 115 ms, serialize 13,043 ms. Synthetic paragraphs: 5,000 → 282 ms, 10,000 → 1,026 ms, 20,000 → 3,679 ms, 40,000 → 14,372 ms (serialize), roughly quadratic. Issue #136 (closed 2026-10-09) reported 9.4 s at 40,000 paragraphs on 1.13.7 and got a patch; 1.13.9 (2026-10-22) is "Improve Markdown serializer performance" [D53, D55, D42, D2].
- [TT] Probe (StarterKit + Markdown, same files): `large` parse 17 ms, serialize 8 ms; `stress` parse 136 ms, serialize 81 ms. With `Table`, `TableRow`, `TableCell`, `TableHeader`, `TaskList` and `TaskItem` registered: `large` parse 367 ms, `stress` parse 40,659 ms, as issue #8458 (open, created 2026-10-09) describes ("Table and TaskList tokenizers make parsing quadratic in document length") [D54, D55, D28].
- [both] Time to render, keystroke latency, scrolling and heap size were not measured (no DOM run); the prototype has to measure them [D55].
- [both] Decoration cost: 1.42.7 fixed quadratic update time for many node decorations in one parent; issue #911 (open, 2019) "Performance problem with multiple block nodes" [D3, D32].

- [PM] Probe: `doc.content.findDiffStart(next.content)` and `findDiffEnd` give the changed range; applying it with `tr.replace` on `hello world foo` → `hello brave world foo` mapped a caret from position 14 to 20 (shifted by the 6 inserted characters). - [PM] prosemirror-history 1.5.1 (2026-09-29): "Fix an issue that allowed remote changes to corrupt the undo history" [D6].

## Unknowns

- Caret stepping over a `[[…]]` chip as one unit, Backspace/Delete removing the whole chip, and the `[[` popover filtered by allowed kinds: no source settles them for either form; a prototype has to measure them in Chromium and WebKit, with the chip at the start of a block, after another chip, and in the middle of a word.
- IME and dead keys next to a chip, in a voice block and in prose (Japanese composition; `^` then `ê`, `¨` then `ü` on Swiss and German layouts): no ProseMirror or Tiptap issue about dead keys was found (searches for "dead key", "circumflex", "umlaut", "diaeresis" on 2026-10-31), which is not evidence that they work; the CDP run covers Chromium only, WebKit would be insertion only, and Windows IME needs the manual checklist. Issue #1585 and prosemirror-view 1.41.4 show chip-like inline nodes have had Windows IME bugs.
- Whether prosemirror-view 1.42.9 plus Tiptap 3.32.2 composes correctly with Backspace during a Pinyin or Japanese composition: #1610 is still open and #8626 (Tiptap's own Backspace handler dispatching an empty transaction) has no maintainer response yet; a prototype pinned to 1.42.9 must repeat the #1610 reproduction.
- Span-level mapping from edits back to source offsets: markdown-it gives block line ranges only and `marked` gives `raw` per token; neither gives inline offsets, and `raw` inside containers (callouts, lists) loses prefixes. Whether an adapter can store per-node source spans and re-emit untouched spans for an edited block (not just untouched blocks) is not shown by any source found; a prototype would have to count bytes changed outside the edit across the manifest edits.
- Front matter in Source mode: whether one component can show the whole file raw with the front matter protected (e.g. a second state with a one-code-block schema in the same view) or whether Source mode needs a second component; edits that touch the body start (delete at start, select-all and type, paste, undo) were not run.
- Write mode as live preview (Markdown of the construct under the caret shown raw): no stock feature in either form was found; a search found Obsidian-style live preview built on CodeMirror 6 and one Tiptap discussion about a decorations API (https://github.com/ueberdosis/tiptap/discussions/8178, read only as a search result); cost of a decoration or node-view approach is unmeasured.
- Rendering performance on the large (247 KB) and stress (2.47 MB) files: only Node parse and serialize times were measured (no DOM); open time, keystroke-to-paint latency (median, p95), scrolling and JS heap need the browser prototype. The 13 s PM serialize time on the stress file and 40 s Tiptap parse with Table/TaskList registered show the shape of the cost, not what a debounced save would cost.
- Svelte 5 node views at scale: `svelte-tiptap`'s `SvelteNodeViewRenderer` and `@prosemirror-adapter/svelte` were read but not run; unmount timing, leaks with hundreds of chips, `$state` props reactivity with `node` replacement, and SSR/SvelteKit settings are unmeasured. Whether an official `@tiptap/svelte` ships is open (PR #7859 closed).
- Applying an external change as a minimal edit that keeps caret and local undo (CE-34.2): the `findDiffStart`/`findDiffEnd` probe covered one text insertion only; behaviour across nodes with attributes (chips, callouts) and with the history plugin (whether the remote-style edit should be in or out of history) was not run.
- Tiptap Markdown tables (with the Table extension) and GFM alignment were not round-trip tested; open Tiptap issues #6768 (table header) and #8458 relate.
- Runtime network and telemetry: only a static grep of package sources and dist files was done (no devtools Network capture of a running prototype); the Link extension opens URLs on click by default.
- Transitive licences of the actual prototype (`pnpm licenses list`) may differ from the clean installs here (21 and 49 packages), especially with a Markdown plugin (`markdown-it-obsidian-callouts` is Apache-2.0) or a Svelte binding.
- Long-term maintenance risk is not settled by sources: ProseMirror has one npm maintainer and moved hosting on 2026-04; Tiptap's Markdown package is documented as an early release with 69 releases in 12 months; both are numbers, not a forecast.
